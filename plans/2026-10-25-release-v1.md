# Release epub-tts v1.0.0

## Decisions

| Area | Decision |
|------|----------|
| Audience | Small invited group. |
| Distribution | Web app / PWA on GitHub Pages at https://thumnet.github.io/epub-tts/. Deploy on merge to main. Tag releases (v1.0.0, ...) with generated notes. Show version and build id in the app. |
| Platforms | iPhone, Android, desktop. Real-device checks stay manual. |
| Voices | English, curated 3-5, chosen after a licence audit. Models stay on Hugging Face (the library's pinned URL). |
| Features | Voice picker, speed control, chapter navigation with continuous playback across chapters, one remembered book, offline use. |
| UI and name | Name `epub-tts`. The log becomes a collapsed Diagnostics panel with a Copy button. Replace the "prototype" strings (index.html title and h1, public/manifest.webmanifest, the Media Session album in src/main.ts). |
| Support | Testers copy the log into a GitHub issue (issue template). No automatic error reporting. No telemetry. |
| Tests | CI on every PR: typecheck, build, unit tests (vitest) and end-to-end tests (Playwright, Chromium and Firefox) with the speech engine mocked. Real-Piper and real-device checks stay manual. Unit tests arrive with the pure modules during the refactor. |
| UI technology | Vanilla TypeScript with a tiny store and a render function. The engine is framework-free. Tripwire: move the UI layer to Vue or Preact if we add a third screen or more than about 8 components that share state. |
| Safety net | Playwright smoke tests on Chromium and Firefox with a mocked speech worker, run in CI. Real-device checks stay manual. |
| iOS lock-screen resume | Accept the limit and document it. Resume after a pause of about 3 to 6 s stops working until the app is in the foreground. Source: owner's own log on one iPhone (iOS 18.7). Not verified elsewhere. |
| Repo licence | GPL-3.0 (the app serves a GPL-3.0 espeak-ng wasm). Not legal advice. |

## Phases

Phases 1, 2 and 6 do not depend on each other. The voice picker in phase 3 depends on phase 1. Phase 4 follows phase 3. Phase 5 depends on the voice storage choices in phase 3.

Status (2026-10-25): phases 1 and 2 are done. Phase 3 is done, pending the owner's phone test.

1. **Voice licence audit** (done, read-only research)
   - Goal: find 3-5 English voices whose terms clearly allow this use.
   - Tasks:
     - Check the model card and the dataset licence of each candidate English voice in the library's list (35 voices). See `node_modules/@mintplex-labs/piper-tts-web/dist/voices_static-*.js`.
     - Output a shortlist with the licence and attribution text per voice.
     - Drop en_US-lessac-medium if its terms fail.
   - Acceptance: every shortlisted voice has a cited licence. The decision about Lessac is recorded.

2. **Release foundation** (done)
   - Goal: make the repo and the app ready for outside testers.
   - Tasks:
     - Add LICENSE (GPL-3.0).
     - Add a third-party notices file (espeak-ng, piper-phonemize, Piper voices, onnxruntime-web, voice credits from phase 1).
     - Rename the prototype strings to epub-tts.
     - Add the version and build id, and show them in the app.
     - Build the collapsed Diagnostics panel with a Copy button.
     - Add a GitHub issue template.
     - Add a tester guide in the README.
   - Acceptance: the build passes. The strings are renamed. The panel works. LICENSE and the notices file are present.

3. **Features** (done, pending the owner's phone test; the voice picker waited for phase 1)
   - Goal: deliver the v1.0.0 feature set.
   - Tasks:
     - Voice picker with the curated list. Use the library's stored, download and remove calls to show what is downloaded.
     - Speed control.
     - Chapter navigation with continuous playback into the next chapter. Pre-generate the first segment of the next chapter while the last segment plays.
     - One remembered book, stored in the browser. Replace it when a new book opens.
     - Saved settings (voice, speed).
   - Acceptance: each feature works on desktop Chromium and on an iPhone. Saved position and resume still work.

4. **Refactor and UI polish**
   - Goal: make the code safe to change, then improve the look.
   - Steps, in order:
     1. Smoke test and CI first. Playwright tests with a mocked speech worker run on Chromium and Firefox in CI.
     2. Split the engine out of `src/main.ts` into modules: worker client, generation pipeline, player, library. Change no behaviour. Make each step its own commit.
     3. Add a small store and one `render(state)` function. The UI is drawn from state. This replaces the scattered DOM writes.
     4. Do a design pass and UI polish.
     5. Do one phone test pass at the end for what automation cannot check: real audio, lock screen, voice download and remove, iOS storage.
   - Acceptance: the smoke tests pass after every step. The UI is drawn from state. The phone test pass is recorded.

5. **Offline PWA**
   - Goal: the installed app works without a network.
   - Tasks:
     - Add a service worker for the app shell and the phonemizer wasm and data. vite-plugin-pwa is a likely tool. Verify this.
     - Voices use the library's own browser file storage (OPFS).
     - Request storage persistence with `navigator.storage.persist()`.
     - Show the offline state and the voice-downloaded state.
   - Acceptance: after one online load and one voice download, the installed app opens and plays offline on an iPhone. The check that Hugging Face downloads work with the chosen caching approach is recorded.

6. **Quality gate**
   - Goal: catch breaks before merge.
   - Tasks:
     - Add vitest unit tests for pure logic: sentence splitting, wav join, segment mapping, saved position. These arrive with the pure modules in phase 4.
     - The Playwright tests and the CI workflow exist since phase 4 (`.github/workflows/ci.yml`). Extend them with unit tests.
   - Acceptance: the workflow is green on a PR. A deliberate break is caught.

7. **Release**
   - Goal: publish v1.0.0.
   - Tasks:
     - Tag v1.0.0 with generated notes.
     - Check the Pages deploy.
     - Check the version shown in the app.
   - Acceptance: the tag and the release exist. The live app shows v1.0.0.

## Findings behind the plan

- **Voice licence.** en_US-lessac-medium comes from the Lessac Blizzard 2013 dataset. Its licence says research purposes only, no commercial use, no distribution outside the agreement, and no use by third parties. This rests on one source pair:
  - https://huggingface.co/rhasspy/piper-voices/blob/main/en/en_US/lessac/medium/MODEL_CARD
  - https://www.cstr.ed.ac.uk/projects/blizzard/2013/lessac_blizzard2013/license.html
- The terms of the other voices were not checked.
- The diffusionstudio mirror shows "License: mit" at repo level. This does not clear the dataset terms. Source: https://huggingface.co/diffusionstudio/piper-voices
- **Voice storage.** piper-tts-web 1.0.5 stores voices in OPFS (`navigator.storage.getDirectory`, folder "piper"). It exposes download, remove and stored. Source: `node_modules/@mintplex-labs/piper-tts-web/dist/piper-tts-web.js`, lines ~146-174 and ~465-495.
- The voice list has 35 English voices (en_US and en_GB) in low, medium and high quality.
- Voices download from https://huggingface.co/diffusionstudio/piper-voices/resolve/main (same file, line 13).
- **iOS storage.** WebKit documents a 7-day cap on script-writable storage for sites without user interaction. Home Screen web apps are exempt. Source: https://webkit.org/tracking-prevention/
- StorageManager `persist()` is supported from iOS 17 and is granted heuristically. Source: https://webkit.org/blog/14403/updates-to-storage-policy/
- Home Screen apps get the same quota as a browser app.
- The exact OPFS and Cache API behaviour on iOS 16.4 to 18 is not confirmed.
- **Service worker.** Workbox documents `maximumFileSizeToCacheInBytes` for precache. Prefer runtime caching for large files.
- The Hugging Face resolve-URL redirect and CORS headers were not verified. Check them before relying on service-worker caching of voices.
- **GPL.** The commonly stated position is that serving the GPL wasm to browsers is distribution. Source: https://www.gnu.org/licenses/gpl-faq.html. This is not legal advice.
- **Phonemizer.** The old build stays for now. See README "Known limitations / maintenance notes".

## Risks

- The voice licence outcome may leave fewer than 3 usable voices.
- iOS offline storage behaviour is not confirmed.
- The app depends on Hugging Face staying up.
- The GPL position is not legal advice.
- The iOS lock-screen resume limit stays.

## Later ideas

### Multi-speaker voices (LibriTTS)

- A multi-speaker voice is one model file with many voices. The model takes a speaker number (`sid`) that picks a learned voice vector. All speakers share one file.
- Candidates:
  - `en_US-libritts-high`: trained from scratch, no Lessac lineage. The dataset is CC BY 4.0 per its card. It has 904 speakers.
  - `en_US-libritts_r-medium`: 904 speakers per its `.onnx.json` and card. It is fine-tuned from Lessac medium, so the Lessac carry-over risk in docs/voice-licence-audit.md applies. The dataset is CC BY 4.0 per its card.
- Blocker: `@mintplex-labs/piper-tts-web` 1.0.5 hard-codes `speakerId = 0` (node_modules/@mintplex-labs/piper-tts-web/dist/piper-tts-web.js, line 388). Also, `src/worker.ts` calls `session.predict(text)` with no speaker option. Choosing a speaker needs a patch or a replacement of that part of the library.
- Other work:
  - Run a listening test to pick a few clean speakers. Voice quality may vary between volunteers (unverified assumption).
  - Write the attribution text for CC BY 4.0.
  - Add a speaker picker to the voice picker.
- A figure of 2306 speakers came up in conversation. The model data says 904. Treat 2306 as unverified and unexplained.
- Status: not planned for v1.0.0. Revisit after the release.
